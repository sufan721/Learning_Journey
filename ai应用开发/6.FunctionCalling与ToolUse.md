# Function Calling / Tool Use — Agent 的手和脚

上一章讲了 Agent 是 LLM + 工具 + 循环。这一章专门讲**"工具"这一块**——它是 Agent 的四肢，也是让 AI 从聊天机器变成应用引擎的关键。

---

## 一句话理解

> **Function Calling（OpenAI 叫法）/ Tool Use（Anthropic 叫法）** 是一回事：让 LLM 知道"我有哪些工具可用"，然后在需要时**输出一个结构化的工具调用请求**，而不是一段自然语言。

```
不是 LLM 真正去"调用"你的函数
而是 LLM 说："我想调用这个函数，参数是这些"
     → 你的代码收到请求
     → 你的代码执行函数
     → 你的代码把结果发给 LLM
     → LLM 基于结果继续
```

> ⚠️ 关键认知：**LLM 从来不执行任何代码，它只输出 JSON**。你的程序才是真正执行工具的主体。

---

## 工作原理（请求→响应→执行→反馈）

```
┌─────────────────────────────────────────────────┐
│ 你的代码                                         │
│                                                 │
│  1. 把"用户问题 + 工具列表"发给 LLM               │
│       ↓                                         │
│  2. LLM 回复：{ "function": "search",            │
│                "arguments": {"q": "今天天气"} }   │
│       ↓                                         │
│  3. 你的代码解析 JSON，调用 search(q="今天天气")   │
│       ↓                                         │
│  4. 拿到结果 "北京晴，25°C"                       │
│       ↓                                         │
│  5. 把结果发给 LLM，让它回答用户                   │
│                                                 │
└─────────────────────────────────────────────────┘
```

## 工具的定义（核心技能）

### OpenAI 格式

```python
tools = [
    {
        "type": "function",
        "function": {
            "name": "get_stock_price",
            "description": "获取指定股票的实时价格",
            "parameters": {
                "type": "object",
                "properties": {
                    "symbol": {
                        "type": "string",
                        "description": "股票代码，如 AAPL、TSLA"
                    },
                    "currency": {
                        "type": "string",
                        "enum": ["USD", "CNY", "HKD"],
                        "description": "货币单位"
                    }
                },
                "required": ["symbol"]
            }
        }
    }
]
```

### Anthropic (Claude) 格式

```python
tools = [
    {
        "name": "get_stock_price",
        "description": "获取指定股票的实时价格",
        "input_schema": {
            "type": "object",
            "properties": {
                "symbol": {
                    "type": "string",
                    "description": "股票代码，如 AAPL、TSLA"
                },
                "currency": {
                    "type": "string",
                    "enum": ["USD", "CNY", "HKD"],
                    "description": "货币单位"
                }
            },
            "required": ["symbol"]
        }
    }
]
```

### 工具描述写得好不好的黄金法则

```python
# ❌ 差的工具描述
{
    "name": "do_stuff",
    "description": "处理数据",
    "parameters": {"data": {"type": "string"}}
}

# ✅ 好的工具描述
{
    "name": "search_customer_by_phone",
    "description": "通过手机号在 CRM 系统中查找客户。输入带区号的完整手机号，"
                   "返回客户的姓名、等级、最近订单。没有查到时不编造，返回空对象。",
    "parameters": { ... }
}
```

**工具描述 = LLM 唯一的使用说明。写不清楚，它就用不对。**

## OpenAI vs Anthropic 详细对比

| 特性 | OpenAI | Anthropic (Claude) |
|------|--------|---------------------|
| **称呼** | Function Calling / Tools | Tool Use |
| **并行调用** | ✅ 原生支持 | ✅ 原生支持 |
| **强制调用** | `tool_choice: "required"` | `tool_choice: {"type": "any"}` |
| **指定工具** | `tool_choice: {"type": "function", "function": {"name": "xxx"}}` | `tool_choice: {"type": "tool", "name": "xxx"}` |
| **无工具模式** | `tool_choice: "none"` | `tool_choice: {"type": "auto"}` (默认) |
| **流式调用** | ✅ | ✅ |
| **JSON Mode** | 独立功能 `response_format` | 通过 Tool Use 实现 |
| **服务端执行** | ❌ 客户端执行 | ❌ 客户端执行（都是你的代码执行） |

### 完整调用示例对比

**OpenAI：**
```python
from openai import OpenAI
client = OpenAI()

response = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "北京今天天气？"}],
    tools=[{
        "type": "function",
        "function": {
            "name": "get_weather",
            "description": "查询天气",
            "parameters": {
                "type": "object",
                "properties": {
                    "city": {"type": "string", "description": "城市"}
                },
                "required": ["city"]
            }
        }
    }],
    tool_choice="auto"  # auto / none / required
)

tool_calls = response.choices[0].message.tool_calls
# → [{"id": "call_xxx", "function": {"name": "get_weather", "arguments": '{"city": "北京"}'}}]
```

**Anthropic (Claude)：**
```python
import anthropic
client = anthropic.Anthropic()

response = client.messages.create(
    model="claude-sonnet-5-20251001",
    max_tokens=1024,
    messages=[{"role": "user", "content": "北京今天天气？"}],
    tools=[{
        "name": "get_weather",
        "description": "查询天气",
        "input_schema": {
            "type": "object",
            "properties": {
                "city": {"type": "string", "description": "城市"}
            },
            "required": ["city"]
        }
    }]
)

# Claude 的 tool_use 块在 content 数组中
for block in response.content:
    if block.type == "tool_use":
        print(block.name, block.input)
        # → get_weather {"city": "北京"}
```

## 实战：做一个完整的 Tool Use 系统

```python
import json
from openai import OpenAI

client = OpenAI()

# ─── 1. 定义工具的实现 ───
def search_knowledge_base(query: str, category: str = "all") -> str:
    """搜索内部知识库"""
    knowledge = {
        "年假": "每年15天年假，入职满1年可用",
        "报销": "报销需在OA提交，审批后3个工作日到账",
        "加班": "加班需提前申请，调休有效期3个月",
    }
    for k, v in knowledge.items():
        if k in query:
            return v
    return f"未找到关于'{query}'的信息"

def send_notification(user: str, message: str) -> str:
    """发送通知"""
    return f"已向 {user} 发送通知：{message}"

# ─── 2. 工具注册表（函数名 → 函数对象） ───
TOOL_MAP = {
    "search_knowledge_base": search_knowledge_base,
    "send_notification": send_notification,
}

# ─── 3. 工具描述（给 LLM 看的） ───
TOOL_DEFINITIONS = [
    {
        "type": "function",
        "function": {
            "name": "search_knowledge_base",
            "description": "搜索公司内部知识库，查询政策、制度、流程",
            "parameters": {
                "type": "object",
                "properties": {
                    "query": {"type": "string", "description": "搜索关键词"},
                    "category": {
                        "type": "string",
                        "enum": ["all", "hr", "finance", "tech"],
                        "description": "分类筛选"
                    }
                },
                "required": ["query"]
            }
        }
    },
    {
        "type": "function",
        "function": {
            "name": "send_notification",
            "description": "向指定用户发送通知消息",
            "parameters": {
                "type": "object",
                "properties": {
                    "user": {"type": "string", "description": "接收人姓名"},
                    "message": {"type": "string", "description": "通知内容"}
                },
                "required": ["user", "message"]
            }
        }
    }
]

# ─── 4. Agent 核心循环 ───
def run_agent(user_query: str, max_turns: int = 10):
    messages = [{"role": "user", "content": user_query}]
    
    for turn in range(max_turns):
        response = client.chat.completions.create(
            model="gpt-4o",
            messages=messages,
            tools=TOOL_DEFINITIONS,
            tool_choice="auto"
        )
        
        msg = response.choices[0].message
        
        if msg.tool_calls:
            # ── LLM 要调用工具 ──
            messages.append(msg)  # 把 tool_calls 消息加入历史
            
            for tc in msg.tool_calls:
                func_name = tc.function.name
                func_args = json.loads(tc.function.arguments)
                func = TOOL_MAP.get(func_name)
                
                if func:
                    result = func(**func_args)
                else:
                    result = f"错误：未知工具 {func_name}"
                
                # 把工具执行结果加入历史
                messages.append({
                    "role": "tool",
                    "tool_call_id": tc.id,
                    "content": result
                })
            # 循环继续，让 LLM 看到结果再决策
        else:
            # ── LLM 直接回复，任务完成 ──
            return msg.content
    
    return "达到最大轮次限制，任务未完成。"

# ─── 5. 使用 ───
answer = run_agent("我入职刚满一年，想请5天年假，审批流程是什么？")
print(answer)
```

## 工具设计的六个要点

| 要点 | 说明 |
|------|------|
| **名称即语义** | `get_weather` 好，`f1` 差。LLM 靠名称判断该用什么 |
| **描述要诚实** | 描述和实际功能要一致。写"查询实时数据"但实际返回的是缓存→ LLM 会做出错误决策 |
| **参数要有约束** | 用 `enum`、`description` 限制参数，LLM 才不会乱编 |
| **返回值要明确** | 工具返回的字符串会直接给 LLM 读，写得越清晰 LLM 用起来越顺手 |
| **错误处理在工具内** | 工具内部 catch 异常返回友好信息，不要抛异常到 Agent 循环 |
| **工具粒度要合适** | 一个工具只做一件事。与其一个 `manage_user(action, data)`，不如 `create_user` / `update_user` / `delete_user` 拆开 |

---

## 何时用 Tool Use，何时不用？

| 场景 | 用 Tool Use？ | 原因 |
|------|---------------|------|
| 查询数据库 | ✅ | LLM 不知道你的数据 |
| 调用外部 API | ✅ | 支付、天气、邮件等 |
| 复杂数学计算 | ✅ | LLM 纯推理容易错 |
| 获取实时日期 | ✅ | LLM 有知识截止日期 |
| 文件读写 | ✅ | LLM 没有文件系统 |
| 简单的文本翻译 | ❌ | 不需要工具 |
| 情感分析 | ❌ | LLM 自己能做 |
| 文本摘要 | ❌ | 同上 |
| 头脑风暴 | ❌ | 同上 |

---

## 一句话总结

> **Tool Use 就是让 LLM 学会"喊帮手"。它不执行代码——它只输出一个 JSON，告诉你的程序"快去调这个函数，参数我给你了"。你的程序跑完函数，把结果塞回去，LLM 再接着说。**

理解了这个"请求-执行-反馈"的三拍节奏，你就掌握了 AI 应用开发最核心的交互模式。
