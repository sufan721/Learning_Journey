# Embedding 与向量数据库 — 让 AI 真正"读懂"你的数据

LLM 很强大，但它有两个硬伤：**知识有截止日期**，而且**不知道你公司内部的事情**。Embedding + 向量数据库就是解决这个问题的钥匙——让 AI 能在你的文档、代码、知识库里"翻书"后再回答。

---

## 一句话理解 Embedding

> **Embedding（向量嵌入）** 就是把一段文字变成一串数字（向量），这段数字承载了文字的**语义**。语义相近的文字，它们的向量在数学空间里也挨得近。

```
"猫"        → [0.12, -0.34, 0.78, ... 768个数字 ...]
"小猫"      → [0.11, -0.32, 0.76, ...]    ← 和 "猫" 很近
"狗"        → [0.10, -0.30, 0.15, ...]    ← 和 "猫" 也近
"苹果"      → [-0.82, 0.45, 0.63, ...]    ← 和 "猫" 很远
"iPhone"    → [0.73, 0.91, -0.25, ...]    ← 和 "苹果" 反而近（语义关联）
```

> 💡 这不是简单的关键词匹配。你的问题是"怎么退？"，文档里写的是"退款流程"——关键词没有重叠，但语义向量能匹配上。

---

## Embedding 是怎么来的？

Embedding 模型是专门训练来生成向量的模型：

```
输入文字 → Embedding 模型 → 输出向量（一串浮点数）
```

常见维度：
- OpenAI `text-embedding-3-small`：512 / 1536 维
- OpenAI `text-embedding-3-large`：256 / 1024 / 3072 维
- 国内 `bge-large-zh`（智源）：1024 维

维度越高 → 语义表达能力越强 → 存储和计算成本也越高。

---

## 用 Embedding 能干什么？

| 能力 | 原理 | 示例 |
|------|------|------|
| **语义搜索** | 把问题和文档都向量化，找最近的 | "怎么退钱" 匹配到 "退款政策" |
| **文本分类** | 相同类别的文字向量会聚在一起 | 自动归类客服工单 |
| **去重/相似度** | 两条相似的文字向量距离很近 | 检测重复提问 |
| **聚类分析** | 把向量聚成几群，发现隐含主题 | 从用户反馈中发现共性痛点 |
| **推荐系统** | 用户喜欢的文章 → 找内容向量最近的 | 看完这篇推下一篇 |
| **RAG 知识库** | 先把文档向量化存好，提问时检索 → 喂给 LLM | 企业知识库问答 |

---

## 相似度怎么算？

向量相似度有三种主流算法：

```
两个向量 A 和 B：

余弦相似度    cos(θ) = (A·B) / (|A|×|B|)    → 只看方向，不看长度
欧氏距离      dist = √(Σ(Aᵢ - Bᵢ)²)          → 看绝对距离
点积          dot = Σ(Aᵢ × Bᵢ)               → OpenAI Embedding 推荐
```

> 💡 **余弦相似度**最常用。值越接近 1，语义越接近。OpenAI 的新 Embedding 模型推荐用**点积**，因为它专门做过归一化。

## 向量数据库 — Embedding 的家

你不可能每次搜索都把几万条文档的向量全算一遍。**向量数据库**就是专门存向量、做快速检索的引擎。

### 为什么需要向量数据库？

传统数据库：
```sql
SELECT * FROM docs WHERE content LIKE '%退款%'   -- 只能关键词匹配
```

向量数据库：
```
输入："我怎么把钱拿回来"
检索：找 Top-K 个向量距离最近的文档
结果：返回"退款流程图.pdf"、"退款政策2026.md"...
```

### 主流向量数据库一览

| 数据库 | 类型 | 特点 | 适合场景 |
|--------|------|------|----------|
| **Chroma** | 轻量嵌入式 | Python 原生，零配置，类 SQLite | 原型开发、小项目、学习 |
| **FAISS** | 向量检索库(Meta) | 极快，纯内存/CPU/GPU 都支持 | 学术研究、百万级检索 |
| **Milvus** | 分布式向量库 | 企业级、分布式、支持混合查询 | 生产环境、亿级数据 |
| **Pinecone** | 云服务(托管) | 零运维、自动扩缩容 | 不想管基础设施的团队 |
| **Weaviate** | 开源向量库 | 自带 Embedding 模块、GraphQL | 中型项目、需要多模态 |
| **Qdrant** | Rust 编写 | 高性能、过滤功能强 | 对延迟敏感的在线服务 |
| **pgvector** | PostgreSQL 插件 | 数据量不大时顺便用 | 已有 PG，不想引入新组件 |
| **Elasticsearch** | 搜索引擎 + 向量 | kNN 搜索 + 全文搜索混合 | 企业搜索平台 |

### 选库速决策

```
个人学习/原型       → Chroma（最简单的体验）
已有 PostgreSQL    → pgvector（零额外运维）
百万级 + 生产环境   → Milvus 或 Qdrant
不想管运维         → Pinecone
需要全文混合搜索    → Elasticsearch
```

## RAG 全流程（Embedding + 向量库的终极用法）

**RAG（Retrieval-Augmented Generation，检索增强生成）** 是 Embedding 最重要的应用场景，把上面讲的串起来：

### 准备阶段（建库）

```
1. 收集文档（PDF、Markdown、数据库记录...）
2. 把每个文档切分成小段落（Chunk）
3. 每个 Chunk 用 Embedding 模型转成向量
4. 向量 + 原文一起存入向量数据库
```

### 问答阶段（查询）

```
1. 用户提问："公司的年假怎么算？"
2. 把问题转成向量
3. 在向量数据库里检索 Top-K 个最相关的 Chunk
4. 把检索到的原文 + 用户问题一起拼成 Prompt
5. Prompt 发给 LLM → LLM 基于提供的上下文回答
```

### 代码骨架

```python
from openai import OpenAI
import chromadb

client = OpenAI()
# 1. 向量库准备
chroma_client = chromadb.Client()
collection = chroma_client.create_collection(name="company_docs")

# 2. 文档入库
for i, doc in enumerate(["年假每年15天...", "加班调休规则...", "报销流程..."]):
    embedding = client.embeddings.create(
        model="text-embedding-3-small",
        input=doc
    ).data[0].embedding
    collection.add(
        ids=[str(i)],
        embeddings=[embedding],
        documents=[doc]
    )

# 3. 问答
question = "年假有多少天？"
q_embedding = client.embeddings.create(
    model="text-embedding-3-small",
    input=question
).data[0].embedding

results = collection.query(query_embeddings=[q_embedding], n_results=3)
context = "\n".join(results["documents"][0])

# 4. LLM 基于检索到的上下文回答
response = client.chat.completions.create(
    model="gpt-4o",
    messages=[
        {"role": "system", "content": f"根据以下信息回答用户问题：\n{context}"},
        {"role": "user", "content": question}
    ]
)
print(response.choices[0].message.content)
```

## 实战中的关键细节

### Chunk 怎么切？

切太小 → 上下文不完整，切太大 → 检索精度差

| 策略 | 大小 | 适用 |
|------|------|------|
| 固定长度 | 512~1024 tokens | 通用场景 |
| 按段落 | 自然段落 | 结构清晰的文档 |
| 语义切割 | 模型判断语义边界 | 高精度要求 |
| 带重叠 | 相邻 Chunk 重叠 10%~20% | **推荐默认做这个**，避免一句完整的话被切断 |

### 用得上的优化技巧

| 技巧 | 效果 |
|------|------|
| **Hybrid Search（混合检索）** | 向量检索 + BM25 关键词检索结合，召回率更高 |
| **Rerank（重排序）** | 检索出 20 条，用更强的交叉编码器重新排序取前 5 条 |
| **元数据过滤** | 只检索"2026年的"、"技术文档分类"下的内容 |
| **HyDE（假设文档嵌入）** | 先让 LLM 生成一个假想的答案，再用这个假答案去检索——准确率更高 |

## 一句话总结

> **Embedding 把语义变成数学，向量数据库让语义搜索飞快，RAG 把它们串起来让 LLM 能读你的私人数据。**

这是目前 AI 应用开发中**最重要的基础设施模式**——企业的知识库问答、文档搜索、客服机器人、代码库问答几乎都跑在这套架构上。
