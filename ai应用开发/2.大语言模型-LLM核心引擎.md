# 大语言模型（LLM）— AI 的核心引擎

如果说 AI 是一个人的大脑，那**大语言模型就是大脑的语言中枢**。它是我们今天能用自然语言和机器对话的根本原因。

---

## 一句话理解 LLM

> **LLM（Large Language Model，大语言模型）** 是一个在海量文本上训练出来的超大神经网络。它的核心能力只有一个：**预测下一个词（token）**。

听起来很简单，但当一个模型参数量大到数百亿、训练数据多到数万亿词时，这个"预测下一个词"的能力就会涌现出翻译、写作、推理、编程等等看起来"智能"的行为。

---

## LLM 是怎么工作的？

### 1. Token（词元）

LLM 不直接理解 "字"，它把文本切成一个个 **Token**：

```
"Hello, world!"  →  ["Hello", ",", " world", "!"]
"你好世界"        →  ["你好", "世界"]
"人工智能"        →  ["人工", "智能"]  或  ["人工智能"]  （取决于分词器）
```

> 💡 不同模型的 Token 切割方式不同。中文通常 1 个字 ≈ 1~2 个 Token。

### 2. 自回归生成（Autoregressive Generation）

LLM 一个字一个字地"接龙"：

```
用户输入: "今天天气真"
LLM 预测: "好"       → "今天天气真好"
LLM 预测: "，"       → "今天天气真好，"
LLM 预测: "适合"     → "今天天气真好，适合"
LLM 预测: "出去"     → "今天天气真好，适合出去"
LLM 预测: "走走"     → "今天天气真好，适合出去走走"
```

每次预测下一个 Token，然后把新 Token 拼到末尾，再预测下一个 — 如此循环，直到输出结束标记。

### 3. 训练的三阶段

| 阶段 | 做什么 | 达到了什么 |
|------|--------|------------|
| **预训练 (Pre-training)** | 给模型喂数万亿词，让它预测下一个词 | 学会语言的语法、知识、推理模式 |
| **监督微调 (SFT)** | 用高质量的 "问题-答案" 对来训练 | 学会"对话"的形式，会回答问题 |
| **RLHF (人类反馈强化学习)** | 人类对模型的多个回答打分排序 | 对齐人类偏好：更有用、更安全、更诚实 |

## 主流 LLM 一览

| 模型 | 开发商 | 特点 | 适用场景 |
|------|--------|------|----------|
| **GPT-4o / GPT-5** | OpenAI | 多模态(文本+图像+语音)、生态成熟 | 通用对话、编程、企业应用 |
| **Claude (Opus/Sonnet/Haiku)** | Anthropic | 长上下文(200K)、安全性强、代码能力强 | 长文档分析、安全敏感场景、编程 |
| **Gemini** | Google | 原生多模态、与 Google 生态整合 | 搜索、多模态应用 |
| **DeepSeek** | 深度求索 | 开源、高性价比、代码能力强 | 本地部署、成本敏感应用 |
| **Llama** | Meta | 开源、社区生态丰富 | 私有化部署、学术研究 |
| **通义千问 (Qwen)** | 阿里 | 中文能力强、开源 | 中文场景、国内应用 |
| **文心一言** | 百度 | 中文理解深、百度生态 | 国内企业应用 |

## 核心概念速查

### 上下文窗口（Context Window）

模型一次能"看到"的最大文本量：

```
上下文窗口 = 你的输入(prompt) + 模型的输出(completion) + 对话历史
```

- GPT-4 早期只有 8K → 今天的主流是 128K~200K
- Claude 支持 200K（约等于一整本《三体》）
- Gemini 可达 200 万 Token

> ⚠️ 注意：不是上下文越大越好 — 在超长上下文中，模型可能在"中间部分"注意力下降（Lost in the Middle 效应）。

### Temperature（温度）

控制输出的**随机程度**：

| 值 | 效果 | 适用场景 |
|----|------|----------|
| `0` | 确定性输出，每次都一样 | 代码生成、数学计算、分类 |
| `0.3~0.7` | 平衡创造性和一致性 | 日常对话、翻译 |
| `0.8~1.0` | 更有创意、更多样化 | 写诗、头脑风暴、创意写作 |
| `>1.0` | 天马行空、胡言乱语 | 基本不推荐 |

### Top-P（核采样）

另一种控制随机性的方式。设定一个概率阈值 `p`（如 0.9），模型只从累积概率达到 p 的 Token 中采样。

> 💡 实践中 **同时调 Temperature 和 Top-P 反而容易出问题**—— 通常只调其中一个即可。

### System Prompt（系统提示词）

在对话开始前给模型设定"角色"和"规则"：

```markdown
你是一个资深的 Python 后端开发工程师。
规则：
- 代码必须带类型注解
- 给出解释，但代码优先
- 不生成测试文件除非我要求
```

System Prompt 是开发者"驯服" LLM 的最重要工具之一。

## 开发者如何与 LLM 交互？

### 1. Chat Playground（网页聊天）

适合快速验证想法，不适合做应用。

### 2. API 调用

开发者真正用的方式。所有主流 LLM 都提供 API：

```python
# 以 OpenAI SDK 调用为例
from openai import OpenAI

client = OpenAI(api_key="sk-xxx")

response = client.chat.completions.create(
    model="gpt-4o",
    messages=[
        {"role": "system", "content": "你是一个有用的助手。"},
        {"role": "user", "content": "用一句话解释什么是递归。"}
    ],
    temperature=0.7,
    max_tokens=200
)

print(response.choices[0].message.content)
# → "递归是一个函数调用自身来解决问题的编程技术，就像俄罗斯套娃一样层层嵌套直到满足终止条件。"
```

### 3. 不同模型的 API 格式

好消息是，**大部分模型都兼容 OpenAI 的 API 格式**。换模型通常只需要改 `base_url` 和 `model` 名称：

```python
# Claude (通过 Anthropic SDK)
import anthropic
client = anthropic.Anthropic(api_key="sk-ant-xxx")
message = client.messages.create(
    model="claude-sonnet-5-20251001",
    max_tokens=1024,
    messages=[{"role": "user", "content": "你好"}]
)

# DeepSeek / 通义千问 等 → 直接兼容 OpenAI SDK，只改 base_url
client = OpenAI(
    api_key="sk-xxx",
    base_url="https://api.deepseek.com"  # 换成对应厂商的地址
)
```

## LLM 的核心局限

| 局限 | 说明 | 应对方式 |
|------|------|----------|
| **幻觉 (Hallucination)** | 会自信地编造不存在的事实 | RAG、联网搜索、人工审核 |
| **知识截止日期** | 训练数据有截止时间，不知道之后的事 | 联网搜索、RAG |
| **缺乏真正理解** | 本质是统计预测，不是真的"思考" | 不要让它做需要精确推理的决策 |
| **数学能力弱** | 纯 LLM 做复杂计算容易出错 | 让模型生成代码来算（Code Interpreter） |
| **上下文窗口有限** | 不能无限塞信息 | 分段处理、向量检索 |
| **Token 成本** | 长对话和大文档处理的 API 费用不低 | 缓存、控制上下文长度、选合适的模型级别 |

## 选择 LLM 的实用框架

做应用开发时，按这个顺序思考：

```
1. 这个任务需要哪种能力？ → 纯文本？多模态？代码？
2. 数据安全要求如何？     → 能不能用云端 API？要不要本地部署？
3. 延迟要求？              → 实时对话？批处理？
4. 成本预算？              → 按 token 计费，计算预估用量
5. 对中文/特定领域的支持？  → 不同模型差异很大
```

一个常见的实战策略是**场景分流**：

- **简单任务**（分类、摘要、提取）→ 便宜的模型（Haiku、DeepSeek）
- **复杂任务**（代码生成、长文档分析、多步推理）→ 强模型（Opus、GPT-5）
- **需要保证质量的关键输出** → 强模型 + 人工审核
