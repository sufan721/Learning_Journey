### 为什么需要数据卷？

Docker容器在删除后，容器内产生的数据也会随之消失。为了：
- **数据持久化**：容器删除后数据不丢失
- **数据共享**：多个容器共享同一份数据
- **方便修改**：在宿主机直接修改文件，容器内即时生效

---

### 三种挂载方式

| 类型 | 语法 | 数据位置 | 适用场景 |
|------|------|----------|----------|
| **数据卷(volume)** | `-v 数据卷名:容器内路径` | Docker管理的宿主机目录 (`/var/lib/docker/volumes/`) | 数据持久化、容器间共享 |
| **目录挂载(bind mount)** | `-v 宿主机路径:容器内路径` | 宿主机任意路径 | 开发时热更新、配置文件挂载 |
| **tmpfs挂载** | `--tmpfs 容器内路径` | 宿主机内存 | 临时缓存、敏感数据(不落盘) |

---

### 数据卷操作命令

| 命令 | 说明 |
|------|------|
| `docker volume create 数据卷名` | 创建数据卷 |
| `docker volume ls` | 查看所有数据卷 |
| `docker volume inspect 数据卷名` | 查看数据卷详细信息(含宿主机实际路径) |
| `docker volume rm 数据卷名` | 删除指定数据卷 |
| `docker volume prune` | 清除未被任何容器使用的数据卷 |

### 如何挂载

在执行 `docker run` 命令的时候使用 `-v 数据卷:容器内目录`，如果数据卷不存在会自动创建。

`-v` 可以使用路径(相对和绝对)，只有在 `docker run` 命令执行时才能进行挂载。

#### 基本示例

```bash
# 数据卷挂载 — 将名为 html 的数据卷挂载到 nginx 的网页目录
docker run -d --name nginx -p 80:80 -v html:/usr/share/nginx/html nginx
```

---

### 详细用法

#### 1. 数据卷挂载（Volume）

Docker自动管理存储位置，**推荐用于生产环境**：

```bash
# 先创建数据卷（可选，-v 会自动创建）
docker volume create mysql-data

# 挂载数据卷运行 MySQL
docker run -d \
  --name mysql \
  -p 3306:3306 \
  -e MYSQL_ROOT_PASSWORD=123456 \
  -v mysql-data:/var/lib/mysql \
  mysql:8.0

# 查看数据卷在宿主机上的实际位置
docker volume inspect mysql-data
```

#### 2. 目录挂载（Bind Mount）

挂载宿主机上的**指定路径**，**推荐用于开发环境**：

```bash
# 将当前目录下的 html 文件夹挂载到 nginx
docker run -d --name nginx -p 80:80 -v ./html:/usr/share/nginx/html nginx

# 绝对路径挂载
docker run -d --name nginx -p 80:80 -v /home/user/html:/usr/share/nginx/html nginx

# 挂载单个配置文件（Windows 注意路径格式）
docker run -d --name nginx -p 80:80 -v ./nginx.conf:/etc/nginx/nginx.conf:ro nginx
```

#### 3. 只读挂载

在容器内路径后面加 `:ro`，容器内**只能读取不能修改**：

```bash
docker run -d --name nginx -p 80:80 -v html:/usr/share/nginx/html:ro nginx
```

---

### `--mount` vs `-v` 的区别

| 对比项 | `-v` | `--mount` |
|--------|------|-----------|
| 语法 | 简洁，三个字段用 `:` 分隔 | 冗长，用 `key=value` 指定 |
| 数据卷不存在时 | 自动创建 | **报错**，需先手动创建 |
| 可读性 | 隐式，需记忆字段顺序 | 显式，一目了然 |
| 推荐 | 简单场景 / Docker旧版本 | **Docker 17.06+ 推荐** |

```bash
# 两种写法等价
docker run -d -v nginx-data:/usr/share/nginx/html nginx

docker run -d --mount type=volume,source=nginx-data,target=/usr/share/nginx/html nginx

# bind mount 用 --mount 的写法
docker run -d --mount type=bind,source=./html,target=/usr/share/nginx/html nginx
```

### 数据卷容器（容器间共享数据）

多个容器可以通过挂载**同一个数据卷**来共享数据：

```bash
# 第一步：创建一个数据卷
docker volume create shared-data

# 第二步：容器A写入数据
docker run -d --name container-A -v shared-data:/data nginx

# 第三步：容器B读取同一份数据
docker run -d --name container-B -v shared-data:/data nginx
```

也可以使用 `--volumes-from` 从另一个容器继承挂载：

```bash
# 先创建一个"数据卷容器"（只定义卷，可以不运行）
docker create --name data-container -v shared-data:/data busybox

# 其他容器从它继承
docker run -d --name app1 --volumes-from data-container nginx
docker run -d --name app2 --volumes-from data-container nginx
```

### 测试案例

#### 需求：
- 创建数据卷 `test-volume`
- 查看数据卷列表
- 运行 nginx 并挂载 `test-volume`
- 进入容器在挂载目录创建文件
- 删除容器后，验证数据是否还在
- 重新运行新容器挂载同一数据卷，检查文件是否存在

```bash
# 1. 创建数据卷
docker volume create test-volume

# 2. 查看数据卷列表
docker volume ls

# 3. 查看数据卷详细路径
docker volume inspect test-volume

# 4. 运行 nginx 挂载数据卷
docker run -d --name test-nginx -p 8080:80 -v test-volume:/usr/share/nginx/html nginx

# 5. 进入容器，创建测试文件
docker exec -it test-nginx bash
echo "Hello Docker Volume!" > /usr/share/nginx/html/index.html
exit

# 6. curl 验证
curl http://localhost:8080

# 7. 删除容器
docker stop test-nginx
docker rm test-nginx

# 8. 重新运行新容器，挂载同一数据卷
docker run -d --name test-nginx2 -p 8081:80 -v test-volume:/usr/share/nginx/html nginx

# 9. 验证数据还在
curl http://localhost:8081

# 10. 清理
docker stop test-nginx2
docker rm test-nginx2
docker volume rm test-volume
```

### 常见场景

| 场景 | 挂载方式 | 示例 |
|------|----------|------|
| MySQL数据持久化 | 数据卷 | `-v mysql-data:/var/lib/mysql` |
| Nginx网站文件 | 目录挂载 | `-v ./html:/usr/share/nginx/html` |
| 配置文件热更新 | 目录挂载(文件) | `-v ./nginx.conf:/etc/nginx/nginx.conf:ro` |
| Redis持久化 | 目录挂载 | `-v ./redis/data:/data` |
| 日志收集 | 目录挂载 | `-v ./logs:/var/log/app` |
| 多个容器共享静态资源 | 数据卷 | `-v static-files:/app/static` |
| 敏感临时数据 | tmpfs | `--tmpfs /tmp` |

---

### 注意事项

1. **目录挂载路径**：使用相对路径时必须以 `./` 或 `../` 开头，否则 Docker 会把它当作数据卷名
2. **权限问题**：容器内用户可能没有权限读写挂载的目录，注意 uid/gid 的对应关系
3. **路径覆盖**：挂载会**覆盖**容器内该路径的原有内容（如果数据卷为空，容器内原有内容会被复制到数据卷中）
4. **镜像构建阶段不能挂载**：`-v` 只在 `docker run` 时有效，Dockerfile 中应使用 `COPY` 或 `ADD`
5. **Windows 路径**：Windows 下使用绝对路径要注意格式，推荐在 Git Bash 中使用 `/c/Users/...` 格式
